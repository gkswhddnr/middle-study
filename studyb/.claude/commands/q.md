GameCodingTest 폴더에서 문제 하나 출제.

영역: $ARGUMENTS

**영역 매핑:**
- 비어있음 / "랜덤" → 모든 카테고리 랜덤
- "초급" / "쉬운" / "기초" / "easy" / "워밍업" → 01_basic.md B1~B60 랜덤
- "중급" / "mid" → 02_intermediate.md M1~M10
- "고급" / "hard" → 03_advanced.md A1~A10
- "그래픽스" / "그래픽" / "gfx" → 04_graphics.md G1~G8
- "모바일" / "최적화" / "mobile" → 05_mobile_optimization.md O1~O8
- "회사" / "company" → 06_company_style.md C1~C12
- 회사명 (카카오/넥슨/크래프톤/데브시스터즈 등) → 그 회사 라벨 문제

**규칙:**
1. solutions/ 폴더 절대 열지 말 것 — 정답 노출 금지
2. 문제 본문 + 함수 시그니처 + 입출력 예시만 그대로 보여주기
3. 출제한 문제 번호는 대화 컨텍스트에 기억해두기 (사용자가 나중에 "채점해줘" / "힌트" 라고 자연어로 말할 때 참조용)
4. 끝에 안내: "다 풀면 코드 붙여서 보내주고, 막히면 '힌트' 한마디만"

**출제 형식: 프로그래머스 표준** (한국 게임사 다수가 쓰는 형식)

다음 6개 섹션을 모두 포함:

1. **제목 헤더**: `📝 [번호] [제목]` (게임적 제목으로 재포장해도 OK, 예: B21 "FizzBuzz" → "용사의 진군")
2. **### 문제 설명**: 배경 스토리 1~2문단 + 규칙 명확히
3. **### 제한사항**: N 범위, 입력 조건 등 (불릿)
4. **### 입출력 예**: 표 형식, **최소 2개 케이스** (가능하면 3개 — 일반 / 경계 / 특수)
5. **### 입출력 예 설명**: 적어도 입출력 예 #1은 단계별로 풀이 흐름 설명
6. **### 함수 시그니처**: `Solution` 클래스 안의 `solution` 메서드 형태
   ```csharp
   public class Solution {
       public [반환타입] solution([매개변수]) {
           // 여기에 코드를 작성하세요
           return [기본값];
       }
   }
   ```

**마무리:** "다 풀면 코드 붙여서 보내주세요. 막히면 \"힌트\"."

**주의:**
- 문제집 파일의 본문이 짧으면 위 형식에 맞게 **확장**해서 출제 (배경 스토리, 추가 예시 작성)
- 단, 문제 본질은 절대 바꾸지 말 것 — 입력/출력 정의가 똑같아야 정답 파일과 채점 가능
- 객관식 문제(07_cs_quiz.md)는 위 형식 안 따라도 됨, 객관식 그대로
- 04_graphics, 05_mobile_optimization의 개념 답안 문제도 위 형식 안 따라도 됨 — 질문형 그대로
